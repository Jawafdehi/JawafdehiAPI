# NGM → Jawafdehi frontend integration plan

_Drafted 2026-06-28. Goal: **retire the standalone NGM public website and serve
all NGM surfaces from the Jawafdehi React app** (`/damodaha-volunteer/frontend/`),
backed by the monolith's NGM read APIs (`/ngm/api/...` on `:48000`). This doc is
the plan of record; it does not change code._

See the NGM architecture and unified-search frontend migration notes for context.
Architecture source of truth: `../../ARCHITECTURE.md`.

---

## 1. The reframe: what "NGM frontend" actually is

NGM has **no React app**. The existing NGM public "website" is a **static surface
published to Cloudflare R2** at `ngm-store.jawafdehi.org`, generated by
`/damodaha-volunteer/ngm/ngm/index/build_index.py`:

- a **hierarchical JSON browse tree** (every `IndexNode` → its own JSON file,
  `$ref` to children, leaves carry manuscripts, `next` links for pagination), and
- **per-document crawlable HTML landing pages** (`_render_document_html`) with
  title/description, role-labelled source links (RAW / ALTERNATE / SOURCE_PAGE /
  MARKDOWN / PERMALINK), an optional full-text body, and embedded **schema.org
  JSON-LD** (`CreativeWork`).

So this project replaces a **static-publish surface** with **dynamic React pages**
plus **SSR + sitemaps for crawlability parity**, then decommissions the R2 publish.

## 3. The SEO contract: IRI = sitemap `loc` = SPA route

The discovery layer (`jawafdehi-platform/monolith/discovery/`) already defines
`EntitySitemap`, `MaterialSitemap`, `CourtCaseSitemap`, `CaseSitemap`, and
`_CorpusSitemap.get_urls` emits **each resource's canonical IRI verbatim as the
sitemap `<loc>`** (it deliberately bypasses Django's Site-domain prefixing). So the
public crawlable URL *is* the IRI path. This pins route names, backend URL
synthesis, and SSR all at once:

| Type | Canonical IRI (= sitemap `loc`) | Required SPA route | Detail API |
|---|---|---|---|
| Material | `https://jawafdehi.org/material/<source>/<ident>` | `/material/*` (splat) | `GET /ngm/api/materials/<source>/<ident>` (JSON-LD) |
| Court case | `https://jawafdehi.org/courtcase/<court>/<case_number>` | `/courtcase/*` (splat) | `GET /ngm/api/courts/<court>/cases/<number>/` (+ `/hearings`, `/entities`, `/documents`) |
| Entity (✅ done) | `…/entity/<tail>` | `/entity/*` | `GET /nes/api/entities/<tail>` |

Routes **must** be `/material/*` and `/courtcase/*` (NOT `/court-case/`) to match
the sitemap `loc`. This is the exact pattern already shipped for entities
(`_entity_frontend_path` + `/entity/*` splat → `NesEntityProfile`).

## 4. Current state — the "continue from here" base

The unified-search FE migration is **uncommitted working-tree changes** in
`frontend/` with **3 unresolved merge conflicts** (the immediate blocker):

- `UU src/components/search/SearchFilters.tsx`
- `UU src/pages/ArchiveSearch.tsx`
- `UU vite.config.ts`

Already present and working:
- Unified search lists **Materials** + **Court cases** as types/tabs/filters/result
  cards, bilingual (`SearchTabs.tsx`, `SearchFilters.tsx`, `SearchResultCard.tsx`).
- `CourtCaseCard.tsx` component (renders parties-by-role, hearings, status, etc.).
- FE types `CourtCase`, `CourtCaseHearing`, `CourtCaseEntity` in `types/jds.ts`.
- SSR scaffolding: `entry-server.tsx` (`renderToString` + `StaticRouter` +
  per-route `prefetch()` + react-query dehydrate + Helmet), `entry-client.tsx`.
- Discovery sitemaps already wired for material + courtcase IRIs.

### Gaps to close
1. **Dead clicks.** `App.tsx` has **no `/material/*` or `/courtcase/*` routes**, so
   every NGM search hit lands nowhere. Backend `_frontend_url` returns the **raw
   IRI** for material/courtcase (not a relative SPA path) — needs the entity-style
   host-strip.
2. **Mis-pathed / missing API clients.** `getCourtCase()` in `jds-api.ts` hits the
   **dead legacy proxy** `/ngm/court_case/<id>` — must move to
   `/ngm/api/courts/<court>/cases/<number>/`. No FE clients exist for materials,
   hearings, case-entities, documents, or firms.
3. **No detail pages** for material or court case.
4. **No browse pages** (no NGM analogue of `Cases.tsx` / `Entities.tsx`).
5. **No nav entry / cross-links** from Jawafdehi cases to their court cases.
6. **R2 site still live** — publish job, redirects, SEO parity all outstanding.

## 5. Phased plan

### Phase 0 — Unblock (do first)
- Resolve the 3 merge conflicts; get `frontend/` building + vitest green; commit
  the in-flight unified-search work (author `oopsy <oopsy@claudy.com>`).
- Fix `getCourtCase()` → `/ngm/api/courts/<court>/cases/<number>/`.
- Add typed API clients: `getMaterial(iri|source,ident)`, `getCourtCaseHearings`,
  `getCourtCaseEntities`, `getCourtCaseDocuments`, `getBlacklistedFirms`. Decide
  client home (extend `jds-api.ts` vs. a new `ngm-api.ts` — lean new `ngm-api.ts`).
- **Exit:** search FE green and committed; clients point at live `/ngm/api/...`.

### Phase 1 — Materials (real data, 2,122 rows — fully verifiable now)
- **Backend:** `_frontend_url` material branch → strip IRI host to relative
  `/material/<source>/<ident>` (mirror `_entity_frontend_path`). Add a regression
  test alongside the entity-path test.
- **FE:** `/material/*` splat route → new `MaterialProfile` page. Fetch
  `/ngm/api/materials/<tail>` (JSON-LD), render bilingual name/description,
  role-labelled source links, full-text/transcript fallback, publication date —
  matching what the old R2 HTML page showed.
- **SSR:** add the `/material/` branch to `entry-server.tsx` `prefetch()` and emit
  schema.org JSON-LD via Helmet (parity with `_render_document_html`'s JSON-LD).
- **Verify:** Playwright click-through from a material search hit → detail page;
  deep-link; graceful 404; responsive. (Real data exists, so this is end-to-end.)

### Phase 2 — Court cases (build now, verify against fixtures)
- **Backend:** `_frontend_url` courtcase branch → `/courtcase/<court>/<case_number>`.
- **FE:** `/courtcase/*` splat route → `CourtCaseProfile` page reusing
  `CourtCaseCard` (parties-by-role, hearings timeline, status, documents tab via
  the composite sub-resource endpoints).
- **Fixtures:** seed a handful of court rows into the Postgres `ngm` DB + reindex
  (`reindex_all`) so cards/pages render against representative data. Document the
  seed script; keep it out of prod.
- **Verify:** Playwright against the seeded fixtures. Flag real court ingest as the
  separate NGM workstream that flips this from fixture-verified to live.

### Phase 3 — Browse pages + nav + cross-links
- **Browse:** `Materials` and `CourtCases` list pages (analogues of
  `Cases.tsx`/`Entities.tsx`), powered by unified `/api/search/` with the existing
  facets/sort (type-scoped). Reuse the search result cards.
- **Nav:** add an NGM section entry (decision in §6 on framing — unified vs.
  distinct section).
- **Cross-links:** Jawafdehi `CaseDetailBanner` already parses `court_cases`
  strings — link those to `/courtcase/<court>/<number>` now that the route exists.

### Phase 4 — Retire the R2 site
- Confirm SSR + JSON-LD parity against the old per-document HTML; confirm the
  material + courtcase sitemaps cover the corpus.
- Redirect `ngm-store.jawafdehi.org/...` (both the JSON tree and the per-document
  HTML paths) → the canonical SPA IRI paths. Define the redirect map from the old
  `document_html_relpath` scheme → `/material/...`.
- Turn off the `build_index.py` R2 publish job. Keep R2 as raw-object store
  (`uploads/`) — only the *index/HTML publish* is retired, not document storage.

**Pending:**

  landing/nav/breadcrumbs. Affects Phase 3 nav + browse-page identity.
- **API client home:** extend `jds-api.ts` vs. new `ngm-api.ts` (lean new file).
- **R2 redirect ownership:** where the `ngm-store` → SPA redirect map lives (Worker
  `frontend/worker.ts` vs. Cloudflare rules).

## 7. Risks / watch-items
- **GOTCHA carried from the search migration:** FE API clients default their base
  URL to **production absolute URLs**; compose must set same-origin relative bases
  so the vite proxy is used (see [[unified-search-frontend-migration]]). Any new
  `ngm-api.ts` must follow the same env-driven base pattern, and `/ngm` must stay
  in the vite proxy allowlist.
- Court fixtures must never leak to prod; gate the seed behind a dev-only command.
- Material JSON-LD can carry scraped HTML garbage in some fields (known NES
  importer artifact) — the detail page should render defensively.
- SSR `prefetch()` for IRI-splat routes must tolerate 404 / partial data without
  throwing (the home-page `.replace` crash was this class of bug).

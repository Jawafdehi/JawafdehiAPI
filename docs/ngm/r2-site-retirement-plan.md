# NGM R2 static-site retirement plan

_Drafted 2026-06-29. The NGM public surface is a **static tree published to
Cloudflare R2** at `ngm-store.jawafdehi.org` (hierarchical JSON browse index +
per-document crawlable HTML), generated by `ngm/index/build_index.py` and uploaded
by `ngm/index/publish.py`. With NGM materials + court cases now served as React
pages on the Jawafdehi SPA (`/material/*`, `/courtcase/*`, browse + search), this
static surface can be retired. This is an **ops/infra change** — it is NOT executed
in code here; it requires deliberate, confirmed steps (Cloudflare config + turning
off a production publish job). See [[ngm-frontend-integration]]._

## What exists today (the surface to retire)
- **R2 bucket** published to `ngm-store.jawafdehi.org`:
  - `index-v2.json` + `indices/<date>/…` — the hierarchical JSON browse tree
    (every node a file, `$ref` to children, leaves carry manuscripts).
  - `d/<id-segments>.html` — per-document crawlable HTML landing pages
    (`document_html_relpath`: `ngm:ciaa-press-release:1234` → `d/ngm/ciaa-press-release/1234.html`),
    each with title/description, roled source links, and embedded schema.org JSON-LD.
  - `uploads/…` — the RAW source files (PDFs etc.). **KEEP these** — only the
    index/HTML *publish* is retired, not document storage.
- **Publish job:** `publish()` in `ngm/index/publish.py` (staging dir → R2, then
  prunes stale managed keys). Invoked by the NGM batch pipeline / cron.

## New canonical destinations (already live on the SPA)
| Old R2 path | New SPA path |
|---|---|
| `d/<id-segments>.html` (a material doc) | `/material/<source>/<ident>` |
| court-order doc (`ngm:court-order:<court>:<case_number>`) | `/courtcase/<court>/<case_number>` |
| `index-v2.json` / browse tree | `/materials` and `/courtcases` browse pages |

Discovery parity is already met by the monolith's IRI-driven **sitemaps**
(`MaterialSitemap`, `CourtCaseSitemap` in `monolith/discovery/`) + **SSR + JSON-LD**
on the new detail pages — so crawlers keep a server-rendered, structured surface.

## Retirement steps (execute deliberately, with confirmation)
1. **Pre-flight (no prod change):** confirm SSR + JSON-LD parity on a sample of
   `/material/*` and `/courtcase/*` pages vs. the old `d/*.html`; confirm the
   material + courtcase sitemaps enumerate the corpus.
2. **Redirects (Cloudflare):** add 301s from `ngm-store.jawafdehi.org/...` to the
   canonical SPA paths. Two rules:
   - `d/<segments>.html` → derive the material IRI tail and 301 to
     `/material/<source>/<ident>` (or `/courtcase/...` for court-order ids). The
     mapping is the inverse of `document_html_relpath` + `build_material_iri`.
   - `index-v2.json`, `indices/*` → 301 (or 410) to `/materials`.
   Implement either as Cloudflare redirect rules or in the SPA edge Worker
   (`frontend/worker.ts` already does 301 patterns for legacy case URLs).
3. **Stop the publish job:** disable the `publish()` invocation in the NGM
   pipeline/cron. **Do NOT delete the R2 objects yet** — leave them as a fallback
   until redirects are confirmed in production. (Deleting prod data needs explicit
   sign-off per the production-safety rules.)
4. **Decommission (later, confirmed):** once redirects are verified and traffic has
   drained, optionally remove the stale `index-*.json` + `d/*.html` objects. KEEP
   `uploads/` (raw files are still referenced as RAW source links).

## Open items / ownership
- **Redirect host:** Cloudflare rules vs. `frontend/worker.ts` — the Worker already
  owns `ngm-store`? confirm which hostname the Worker serves before choosing.
- **Inverse mapping code:** the `d/*.html` → IRI redirect needs the exact inverse of
  `document_id → (source, ident)`; write + unit-test it wherever the redirect lives.
- **Court-order docs** were published as material HTML under a `court-order` id but
  their canonical home is `/courtcase/*` — make sure the redirect routes them there,
  not to a `/material/court/...` page.
- This plan does not turn anything off yet — it is the checklist for when the
  decommission is scheduled.
